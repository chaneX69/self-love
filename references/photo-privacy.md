# 用户照片隐私与参考库边界

## 明确条款

**self-love 不会自行留存用户上传的照片，亦不会将用户照片及其生成图用作参考模板、风格样本、训练或微调依据。视觉参考仅限经核实的电影截图及其可追溯的原像素裁切小样。**

用户照片只作为当次任务的内容、身份、构图与颜色分析输入。成品获得认可不等于允许收录，不把已生成图反复喂入参考库，不从私人照片建立跨任务模板。当前任务必要的局部修改可以使用同任务成品，但它仍是编辑目标，不是可长期收藏的风格参考。

## 禁止进入技能的内容

- 用户原片、生成图、测试版本、对比图、缩略图、人脸裁切及其他个人照片小样。
- 从上述图片提取的私人色卡、直方图、语义掩膜、人脸／特征向量、嵌入及照片内容描述；不得换成文本或数值形式绕过规则。
- 关联个人图片的文件名、编号、哈希、本机路径、EXIF／GPS、拍摄地点与日期、含私人内容的提示词或逐图测试报告。
- 指向这些资料的软链接、外链、HTML内嵌图片、Base64载荷、示例、缓存、回滚副本、训练集或微调任务。

上述限制覆盖活跃 skill、完整目录备份、导出目录、GitHub仓库及发布附件。`.gitignore`只是防误提交措施，不能替代实际检查和清除。保留通用流程教训时去掉照片特征、逐图数字、身份线索、来源路径与成功样片索引。

## 当次处理与保存

1. 读取用户当次提供的原照，不为了收藏或训练而另存输入副本；电影素材收录和用户照片处理是两个独立流程。
2. 为完成当次任务必需的计划、替色表、临时小样和验证报告只写入技能外的私有工作区，不纳入跨任务检索或参考库。用户未要求保留的临时副本在交付后清理；不删除用户原文件或需要交付的成品。
3. 长期保存私人照片、结果或逐图报告需另有明确授权及指定的私有位置，不能由“上传照片”“认可成品”或“学习画风”推断授权。现有私人项目文件不因清理 skill 而自动删除。
4. 即使用户允许在私有项目留存，也不得将这些材料放入本 skill 的参考库、训练资料、备份包或公开仓库。复用视觉语言始终回到电影证据。
5. 本 skill 本身不训练或微调模型，也不主动创建、上传个人照片训练集。本规则不等于外部平台的隐私保证；外部宿主、图像工具和云服务的日志／数据政策以实际设置与授权为准，不承诺 skill 无法控制的“服务端零留存”。

## 可保留的证据

电影整帧及电影裁切小样可按[保留规范](library-retention.md)入库，同时保留其色卡、颜色比例、色阶、分类、纹理测量与学习总结。电影来源与裁切坐标必须可追溯；未知来源图片不能因为文件名像剧照就进入白名单。未经核实的图先拒绝发布，而不是自动纳入电影清单。

## 执行检查

`match_photo_palette.py`拒绝将照片计划、原片、照片核验记录或分析输出放在 skill 目录内；输出JSON与HTML都检查，解析软链接后的目的地也检查。`check_acceptance_record.py`对原照、成品、计划、输入记录和输出报告使用同一私有目录边界，且不覆盖已有报告。分析脚本不自动训练、不收藏照片、不把照片数据回写电影库。

在维护结束及更新完整目录备份前执行：

```bash
python -B scripts/verify_reference_privacy.py
python -B -m unittest discover -s scripts -p 'test_*.py'
```

核对每个随包媒体文件是否与电影清单的文件哈希、尺寸及像素哈希一致；扫描未登记图片、隐藏缓存、软链接、压缩载荷、嵌入图片与机器路径。未来增加电影小样时须先扩展具有原帧、坐标和像素核验的清单与检查，再允许入包。该程序检查的是已核实清单的一致性和常见泄漏渠道，不是能识别任意文本隐私的万能检测器；仍须人工查看新增媒体并审阅描述。技术通过不等于授权公开电影版权素材，也不代表用户照片效果已通过。

只发布经过检查的 `self-love/` 完整目录，不发布其上级私有项目、照片输入／输出目录、原件索引或Obsidian数据库；不附ZIP。发布动作须另获用户确认。
