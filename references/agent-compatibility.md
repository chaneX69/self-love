# 跨智能体接入与验收

接入文档核对日期：2026-09-30；双版本约定更新：2026-10-01。目标是迁移完整工作流，不是缩短提示词。规则与698帧数据共用一份，作者本机用完整版，GitHub用全部色卡与纹理小样版，详见[双版本](crop-editions.md)。当前公开发布已获作者授权，但不授权自动安装、付费或向新第三方传输用户照片。

用户最新指定上线只上传未打包压缩的完整 `self-love/` 目录，不上传或附带ZIP。平台接入优先使用完整目录或仓库中的对应目录；遇到仅接受压缩上传的入口，标记该接入方式不符合当前要求，不自动改格式或删除参考数据。

所有宿主共同执行[照片隐私条款](photo-privacy.md)：skill不自行留存用户照片及生成图作为参考模板或训练依据，视觉参考仅限电影截图及其小样。当次私人输入、结果和分析放技能外，不写入可分发目录或目录备份；宿主自身的日志与模型数据政策另行核实，不以skill条款代替平台承诺。

## 能力契约

宿主先核实当前会话实际具备以下能力，不根据品牌名推断：

| 阶段 | 必需能力 | 不足时的处理 |
| --- | --- | --- |
| 读取 | 能访问SKILL.md、专项文档、完整数据和相关原件 | 列出缺少的文件；不能只读摘要后称全量比较 |
| 观察 | 真正查看原照、候选像素局部及成品 | 不能以文件存在或文件名代替视觉核验 |
| 测量 | Python及声明依赖，执行脚本并读取真实JSON输出 | 不编造色卡、直方图、像素比例或匹配结果 |
| 转绘 | 支持原图编辑，并能区分编辑目标与少量风格参考的图像工具 | 可交付已完成的分析，但明确尚未生成成品；不得自动换成滤镜或纯文生图 |
| 验收 | 能取回并实际查看输出、读取像素与尺寸 | 工具成功不是效果通过；暂时无法回读则标记待验收 |

远程工具须先确认隐私、用户授权、凭据和费用范围。工具支持几张参考图、哪些参数、是否可重绘、是否能保留原比例，均以当前实际工具接口为准；不要把Codex的参数名移植到别的接口。缺能力时保留相同质量门槛，不把它包装成“降级兼容成功”。

## 通用文件与脚本

- 通用入口只依赖标准`name`、`description`与Markdown正文；平台专属元数据属于适配层。相对路径以实际技能根目录为基准，不能从安装者的任意工作目录猜测。
- `agents/openai.yaml`是可忽略的Codex界面配置；其他宿主直接读根目录SKILL.md即可取得相同规则，不依赖`$self-love`语法。
- 本机已使用Python 3.12执行数值脚本。依赖声明在`scripts/requirements.txt`；新环境须真实安装并测试。虚拟环境、缓存与运行输出放技能外，不分发作者机器的运行时。
- 在技能根目录，以当前环境的Python执行以下检查；Windows等环境须使用其实际解释器与路径引用规则。安装依赖可能联网，遵守该环境的授权流程。

```text
python -m pip install -r scripts/requirements.txt
python -m unittest discover -s scripts -p "test_*.py" -v
python scripts/match_photo_palette.py --help
```

实际匹配的采样计划和复核JSON契约见[全库流程](full-library-workflow.md)。CLI只是可复用分析步骤，不包含任何已接通的远程绘图服务。

### 原像素证据

完整版84张代表帧通过 `reference_sources.py` 相对定位；其余原件由私有 `SELF_LOVE_ARCHIVE_INDEX` 定位。公开版不含整帧，全部698帧色卡均有可追溯的原像素小样，由 `palette_evidence.py` 核验文件、坐标与像素哈希后使用。小样上下文不足时须补充合法证据，不假装已具备完整场景。使用者可配置自己的原件索引，键为原件SHA-256，值为实际可访问路径；索引不进入公开目录。

没有外部索引的迁移检查应指向空JSON索引，禁止借作者本机原件过关。公开版可独立核验22,336个色卡上下文与548个纹理小样，但不是698帧整图像素库；省略区域不可重测，不能声称完全替代整帧。两版颜色检索仍覆盖全部698帧。

## 平台差异

### Codex

当前官方本地发现路径包括项目或用户的`.agents/skills/<name>/`；本文不自动移动既有安装。根SKILL.md是通用入口，Codex界面元数据独立放`agents/openai.yaml`。当前本机会话已在使用该技能，迁移后仍要验证实际发现与权限。[官方技能文档](https://learn.chatgpt.com/docs/build-skills)

本机工具映射：先用`view_image`打开本地原照；编辑默认使用内置`image_gen`。所有目标图片有路径时使用`referenced_image_paths`；存在无路径目标时按工具说明选择近期图引用机制，不能同时传入两种机制。工具名与参数仅在当前宿主实际提供时使用，不要求其他平台实现同名工具。

### Claude Code

官方支持项目`.claude/skills/self-love/`或用户`~/.claude/skills/self-love/`，以SKILL.md加载，也可通过`/self-love`调用。其他Claude产品的技能同步与路径不可自动当成Claude Code本地行为。[官方技能文档](https://code.claude.com/docs/en/skills)

用当前会话的文件／图像读取工具观察、终端执行同一Python脚本；图像编辑须另外确认当前会话已连接的工具或服务。不能把“能读取skill”写成“已具备Codex内置绘图能力”。尚未在Claude Code完成本技能真实导入和转绘测试。

### WorkBuddy

官方文档确认本地技能包导入。通过“添加技能／上传技能”导入时，实际检查版本、包布局、体积限制和文件是否完整加载，不把文件拖入普通对话当成安装成功。[官方导入说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)

开放平台的市场提交规范另要求`description_zh`、`description_en`、`version`、`author`等字段。正式提交时由同一规则源产生该平台需要的元数据，发布作者名和版本须所有者确认；未确认不虚构字段或提交。市场规范与普通本地导入结果分别核验。[官方开发结构](https://open.workbuddy.cn/docs/skill)

Python分析与图像编辑分别检查实际工具；不把支持脚本或MCP当作已接通绘图。尚未完成本技能在WorkBuddy的导入、脚本和成品验收。

### 豆包相关目标

“豆包”可能指聊天客户端、工作模式或使用豆包模型的智能体宿主，不能将模型能力等同于某个产品的文件系统、脚本或技能导入能力。当前等待用户确认具体目标，保持两条接入路线，不自动改用另一个产品。

- 豆包聊天客户端：官方功能说明提到可定制智能体，但本次未确认其可直接导入本技能的标准目录、执行Python或完整读取约200MB资料。可在能力核实后使用同一规则与资料作为任务依据；没有完整分析与图像工具时只标“部分流程可用／待接入”，不能称全功能适配。[官方功能说明](https://www.doubao.com/legal/feature_intro)
- 使用豆包模型的可执行智能体：火山方舟官方Skills文档的索引内容说明了自定义技能上传与Agent绑定途径，但它不证明豆包聊天客户端具备同一入口。本次网页正文受JavaScript限制，尚未完成其上传规格、体积限制和实际账号验证；确定产品后重新核实并测试，不直接把一个目录当成已部署服务。[方舟Skills文档](https://docs.volcengine.com/docs/ark/skills?lang=zh)

### 其他主流智能体

对采用Agent Skills标准的其他宿主，继续使用同一完整目录，逐一核对发现位置、元数据、工具权限和图像编辑能力。未列入实测记录的产品不自动获得兼容承诺；新增平台不新增另一份会漂移的风格正文。[Agent Skills标准](https://agentskills.io/specification)

## 发布验收矩阵

逐平台记录，不用一个“支持”标签掩盖不同完成度：

| 验收项 | 通过证据 |
| --- | --- |
| 格式 | 平台校验通过，必要元数据无虚构值 |
| 加载 | 在目标应用实际发现技能，读取一次专项规则及数据 |
| 数值执行 | 同一测试样本和参数产出可复核的匹配与统计，包含原件缺失的失败路径 |
| 图像工具 | 真实工具接受原照和指定参考角色，并返回可读取图像 |
| 效果 | 同一原照按内容、配色、材料、脸、反射、四种纹理逐项验收 |
| 权限与资源 | 不泄漏私人路径或凭据，不复制原照入包，不减参考图以蒙混平台限制 |
| 用户批准 | 技术通过与用户效果认可分开，不凭本地测试自动发布 |

此时只有当前Codex工作环境与本机脚本的既有运行证据；新增平台仍需实机验证。工具适配不会解决尚未完成的全库纹理语义占比，不得据此提升其完成状态。
