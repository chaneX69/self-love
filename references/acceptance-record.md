# 当次验收记录与停止规则

本页统一验收状态、版本和次数口径；具体画法及逐项观察仍见[提示与验收](prompt-and-review.md)。不增加第二套画风，也不替代实际看图。记录、原照和成品都在技能外的当次私有工作区，遵守[隐私条款](photo-privacy.md)。

## 生成前固定，生成后复查

先完成内容清单、电影像素材质核验与替色表，冻结当次计划及其哈希。计划写入 `source_sha256` 和非空 `acceptance_targets`：原比例与允许误差、主要ROI及排除区、源与目标颜色／L*范围、整图分位、亮暗排序、逐人物身份与笔线目标、四项纹理落点、附加效果权限。数值必须实测；没有依据就标未验证并阻断对应前置检查，不填任意阈值凑完整。

验收不能见到成品后才放宽目标。确需改目标时说明用户新要求或新证据，保留原计划与本次未通过的事实；新计划属于后续明确授权的测试，不反向把旧图改判通过。计划哈希只证明内容未变，不证明它确实在生成前写下。

输出ROI必须对应同一物体、表面和明暗角色，不盲目复用同一组矩形坐标。先查几何和遮挡；轻微绘制边界变化可记录对齐方式及有效重叠区，不能通过移动ROI、只挑少数命中色点或非刚性配准掩盖对象移位。修正纹理、轮廓或光照后，重新核对颜色、明度、面积、身份及所有受影响门槛。未复查项恢复为未验证，不沿用上一版结论。

## 逐项诊断与综合验收

2026-10-01用户明确将单图画面验收改为**各项指标综合达到90%即可通过**。逐项诊断继续记录真实偏差，避免平均分掩盖问题；一项色彩或纹理未精确命中不自动判整图失败。用户原照不可覆盖、隐私边界、输出能否打开、未授权添加内容等非画面安全边界仍单独检查，不能拿美术得分抵消。评分须在看过成品后根据原图、电影证据、定量测量和原尺寸视觉观察作出，明确这是人工综合判断，不伪称算法测得审美比例。

新记录使用`schema_version: 2`，五类权重固定为：内容与构图25、动画造型与人物20、电影配色与光照25、四层印刷与轮廓20、景深及整体完成度10。每类给0至该类满分及具体证据，合计至少90即`visual_threshold_met`；低于90如实保留较佳测试版。未测项不能凭估计给满分，得分必须反映覆盖率与偏差的实际影响。旧`schema_version: 1`记录保留原语义，不自动追改历史结果。综合达到90只证明当次画面达到用户新标准；若要在记录中标为用户明确认可，仍要绑定用户对该成品的反馈。

| ID | 观察／证据 | 适用 |
| --- | --- | --- |
| `technical` | 文件可打开、显示方向、比例、尺寸、格式；不可只凭扩展名 | 全部 |
| `content` | 原照只读、人数、身份锚点、物体清单、位置、透视与遮挡，无新增事实 | 全部 |
| `animated-form` | 忽略纹理和彩边仍是电影式绘制体块，不是照片滤镜或普通平滑插画 | 全部 |
| `face-identity` | 每位主要人物的可见身份锚点和动画重构；遮挡部分不补造 | 有人物 |
| `person-contour` | 每位主要人物在整图和局部均有有意的粗细、停笔、无墨色面；不以彩边替代 | 有人物 |
| `architecture-contour` | 实体窗框与绘制墨线分开，近远、受光和结构的线重不同 | 有建筑 |
| `material-light` | 材料分别响应主光、投影、接触暗部和高光，不凭空换天气／时间 | 全部 |
| `reflection` | 映像、透射、自发光、遮挡分层；镜像不增人数 | 有可辨反射 |
| `depth` | 主体与远景细节、边缘、纹理和彩边按焦点组织 | 全部 |
| `color-plan` | 全库比较、候选实际像素、同材质／光照／明暗角色及排除理由 | 全部 |
| `color-output` | 当前成品对应ROI的实测偏差、面积、整图分位、亮暗排序与整图观感 | 全部 |
| `halftone` | 圆点形态、尺度、落点和留净区，不能把砂粒当网点 | 全部 |
| `hatching` | 绘制排线随形体方向组织，不能把砖缝／衣料结构当排线 | 全部 |
| `screen-mesh` | 原尺寸可辨的低对比细网，不是噪声或缩放摩尔纹 | 全部 |
| `dual-registration` | 两色局部版位差、稳定核心边缘，不是单色光边或全局RGB平移 | 全部 |
| `permissions` | 蜘蛛感应、字幕、故障等当前触发与允许范围；未触发时无新增效果 | 全部 |
| `privacy` | 私人输入、成品与衍生数据不入skill／训练／参考／发布目录 | 全部 |

每个诊断项仍用 `pass`、`fail`、`unverified`、`not-applicable`，以便知道具体哪里不足；适用项不能用不适用跳过。不再要求所有画面诊断项逐项通过才判综合画面达标：它们的偏差反映在上述五类评分中。无证据、未看原尺寸、尚未复测都属于未验证，不能给相应类别无依据的高分。`technical`、`permissions`、`privacy`三个非画面边界仍须通过。

颜色“数值近似”“材质类比”“原像素同材质核验”分开：类比不能通过严格的 `color-plan`；有合格色表也不能自动通过 `color-output`。未找到某种真实材料证据时记录无匹配，不能改写标签冒充已匹配。全库纹理的分类、局部掩膜、完整语义占比也保持分开，不因本次成品四项可见就宣布全库语义测量完成。

现有 `match_photo_palette.py` 的批准接口只接受目录中的色卡ID。如果现行配色规则允许补充选取电影真实表面的非色卡像素，须另外保存原帧／像素哈希、坐标、实际RGB/Lab、材料／照明／明暗角色及目录候选为何不适用的证据。继续保留全库比较，不伪造色卡ID，也不把这条人工补充路径说成已经由该脚本自动批准。

## 版本、反馈与生成次数

正式任务默认一次成图。第二次仅可修正内容与造型基底稳定且位置明确的小偏差，须说明目标及保护项。基底／结构失败时停止正式流程；只有用户明确授权继续测试，才从原照重新测试。改提示、改参数、换底图、换工具均不重置次数。综合90%口径不放松次数诚实记录。

逐次记录调用序号、用途、输出哈希、修正原因。返回多张候选时另列候选，不把筛选后的最好一张说成唯一生成。用户授权追加测试须保留该事实，不能冒充一次成图的上线证据。生成失败但已发出调用也记录在私有执行日志中，不能从耗用次数隐去；下述轻量脚本只统计有产物哈希的记录，无法独立核实完整调用日志。

用户反馈独立记录为 `not-requested`（尚未征询或尚未回复）、`preferred-only`（只比较更喜欢哪版）、`accepted`（明确认可此图）、`rejected`（明确否定此图）。反馈绑定具体成品哈希；局部认可只锁住该局部，不能填整图认可。用户认可可以与技术偏差同时存在，明确否定不能改写成尚未认可。新版本不自动覆盖已选版本。

新记录在综合得分至少90、非画面边界通过且此图被用户明确认可时，才有完整的单图用户验收记录。综合得分达90但用户尚未回复时，可以标记“内部画面达标”，不能冒称“用户已认可”。单图通过不等于流程稳定、跨宿主实测、参考素材获得发布许可或整个skill已上线；这些继续按[发布门槛](release-readiness.md)分别验证。

## 记录一致性检查器

```bash
python -B scripts/check_acceptance_record.py --record /absolute/private/review.json --output /absolute/private/checked.json
```

命令只校验文件哈希、门槛是否遗漏、适用性、反馈绑定和次数声明。**它不看图，不测电影相似度，不自动验证语义，不用来代替人工审图。** `record_consistent: true` 仅表示记录结构和绑定一致。需要让未完成的正式单图验收返回非零退出码时，加 `--require-accepted`；没有该选项时，一份如实记载失败的完整记录也可以退出0。

输入字段如下，不能把模板文字或合成测试中的通过声明用于真实照片：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 新记录为`2`；`1`仅供旧档案原语义核验 |
| `source`、`result`、`plan` | 各含技能外绝对 `path` 与真实 `sha256`；计划为JSON并包含上文的源哈希与目标 |
| `scope` | 布尔值 `people`、`architecture`、`reflections`，以及说明原照实际可见内容的 `evidence` |
| `checks` | 上表全部17个ID，每项含 `status`、`observation`，通过／失败还需非空的 `evidence` 字符串列表，写清观察尺度、区域、参考编号或私人测量证据 |
| `composite_review` | 新记录必填五个固定类别，每类含数值`score`与非空的具体`evidence`；总分满分100，至少90为内部画面达标 |
| `attempts` | 从1连续编号的列表，每项 `number`、`kind`、`result_sha256`；首项为 `initial`；唯一一次 `correction` 须第2项且有 `base_passed: true` 与具体 `reason`；其它测试用 `additional-test`，附用户明确继续的 `authorization` 与 `reason` |
| `user_feedback` | `status`；有反馈时须含同一成品的 `result_sha256` 与真实 `evidence` |

选回先前较佳版本时 `result` 指向那张图，但 `attempts` 不删掉后续测试。检查器不覆盖现有输出，拒绝向任意带 `SKILL.md` 的目录及其软链接写私人报告。现有 `match_photo_palette.py` 的 `color-mapping-reviewed` 仍仅表示色表完成；不能把该报告直接当成本页的成品验收。
